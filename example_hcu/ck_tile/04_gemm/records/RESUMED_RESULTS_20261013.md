# GEMM 恢复迭代：原始证据与结论（2026-10-13）

额度恢复后已继续实验。本文件由 `analyze_resumed.py` 根据原始 JSON 和设备 ELF 元数据生成；审批额度中断已解除。

当前有效库仍为 K32 B bank + scalar B rebase + 静态 wave 分组方案，SHA `22ef3280c50201d0f66966e4fdfe6af75741f5d6dc4a2c46704bb4d7acd73025`。

独立 BP 复测：FC2 **298.726 T**、QKV **307.743 T**、out_proj **285.510 T**、FC1 **306.519 T**；102组/306次广审计通过。**约330 T目标仍未完成**，没有将跨轮最低值当成新有效版本。

环境：ck_yyc，物理HCU4，gfx936，DTK25.10.0-0，CK `5c8ea51ed7ac03bdcc24aeb811d51acc57233b60`；BF16输入/输出、FP32累加。M=18880；HIP event，5次预热、6轮轮换顺序×每轮10次，取轮均值的中位数，关闭profiler。只测试GEMM，不启动H3。

多数新候选仅有四真实shape的二进制分数精确、普通随机误差/finite和输出guard初筛，**不等同于广审计**。CG/CH三种producer另外各102组/306次审计，CJ选择库126组/378次且原库逐位一致；CL–CP共12候选各102组/306次且原库逐位一致，详见分项报告。源码和构建日志按build/attempts冻结保存；各阶段默认关闭新选项的compat均与有效库逐byte相同。

## ISA / counter 依据与限制

- 最终有效库四shape指标在 `results/profile_final_bbase_four_20261013/ANALYSIS.md`：VM完成等待CK/rocBLAS约2.00、2.19、5.92、2.38倍。它们是wave聚合counter，**不是时间占比**，不能相加，也不能单凭此断言全部差额来自内存。
- 有效库的两个B加载已使用相同resource连续发射；没有据此再做重复的“合并加载”。
- 后续精读ISA修正此前过粗的顺序描述：原生0x1791F08–0x1791F40先发出下一相位8条DS读取，再于0x1791F48–0x1791F60发出未来4个B向量，随后继续8条DS读取。CB的点0/4仍是有效的时机对照实验，但不能再称为精确模仿原生顺序；具体负结果不变。原生实际顺序与候选点8的高层顺序相近，差别应继续看真实地址、寄存器和指令调度。
- 目前没有替换H3 GEMM、没有量化、没有E2E测试，不能将这些BF16单核结果表述为模型收益。03_gemm和共享include未修改；不commit/push，不进行目录重排。
